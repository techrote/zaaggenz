# ZG-041 Compose / Research workspace contract

ZG-041 integrates the accepted research surfaces without making research setup part of ordinary music construction. It is a UX/runtime integration only: it does not alter protected source audio, DSP topology, render defaults, project provenance, listening truth, or the explicit ownership of BODY/AUX/SUB/SCULPT processing.

## Workspace boundary

`python -m zaaggenz_runtime` still opens **Compose** by default at `/timeline`. Compose retains phrase editing, rendering, named outputs, playback, save/reopen, export/download and access to the recovered full instrument. No trial, participant or study setup is required to make or render music.

`/research` is an explicit, non-destructive Research hub. It exposes the authoritative current timeline/project identity and routes to:

- **Inspector** for exact-artifact binding, measured pitch/tuning/spectral inspection and before/after proposal comparison;
- **Listening** for exact stimulus freezing, matched comparisons, blinded trial manifests, recorded observations and participant-safe evidence export;
- **Vocal** for local capture/import and proposal-only gesture compilation.

The Research hub contains no mutation script or implicit apply control. Entering it performs no state-changing request. Each accepted research tool retains its existing explicit mutation/capability contract and immutable source provenance.

## State and provenance semantics

The unified `RuntimeSession` remains the sole owner of the current Compose `TimelineDocument`. The Research page displays its timeline revision, retained project head and project SHA-256. Research material derived from an older revision may remain valid historical evidence, but stale Inspector work cannot publish/apply against a newer Compose revision. Listening records remain immutable derived evidence rather than being rebound to the newest project. Vocal output remains a proposal that requires explicit Compose import/apply.

`/api/runtime/bootstrap` now records the workspace boundary explicitly:

- `routes.compose = /timeline`;
- `routes.research = /research`;
- `workspace_policy.default = compose`;
- `workspace_policy.compose_requires_research = false`;
- `workspace_policy.research_state = derived-and-isolated`;
- `workspace_policy.research_apply = explicit-only`.

The participant/trusted Listening capability split is unchanged. The Research hub never receives or renders the server-held trusted token.

## Browser/release identity

The Research page is generated by the unified runtime and carries the current Timeline web-release identity and no-store response headers. Its stylesheet request is pinned to that exact release ID. The runtime server is already part of every unified workspace backend fingerprint, so any Research-hub protocol/content change invalidates an already-open incompatible workspace release. The page permits no script and retains loopback Host/Origin enforcement.

The Compose timeline adds only an explicit link to Research. Mature Compose controls are not moved or removed. Its source-audition disclosure is updated to describe accepted ZG-029 persistent-layer ownership without pretending those layer paths are silently mixed into the phrase-audition surface.

## Acceptance evidence

`tests/runtime/test_zg041_workspace.py` adversarially verifies that Research GETs do not mutate the authoritative Compose session, never disclose the trusted Listening capability, retain the loopback Origin boundary, and publish the explicit workspace policy.

`tests/runtime/browser_zg041.py` is the real-browser switching proof: it advances a Compose revision, enters Research, traverses Inspector/Listening/Vocal, verifies the same authoritative revision throughout, returns to Compose and verifies the editing state survived the switch.

The ZG-041 CI gate also runs the inherited real-browser suites rather than replacing them:

- `tests/runtime/browser.py` — cross-workspace exact-artifact flow and stale-result rejection;
- `tests/timeline/browser.py` — mature Compose editing, named A/B-style outputs, save/reopen and reproducible render playback;
- `tests/listening/browser.py` — matched comparison / blinded A/B-X transport and recorded-response flow.

Windows and Ubuntu run the same focused runtime/unit gate. The browser evidence runs on Ubuntu with pinned Chromium; ZG-009 remains separately triggered by the Compose HTML change and runs its established real-browser timeline evidence on both Ubuntu and Windows.
